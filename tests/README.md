# E2E Testing Notes

このプロジェクトの E2E は、renderer と `canvas` 実入力の統合確認に責務を絞り、UI 配線や HUD 文言の大半は unit テストで担保します。

## 方針

- E2E はアプリ起動、`canvas` 表示、カメラ回転、ズーム、paint 中の入力抑制など、実ブラウザ統合でしか確認できない最小ケースを担当します。
- HUD 文言、モード切替、ボタン配線、選択サマリー更新、terrain 編集の state 反映は、可能な限り unit テストで検証します。
- `canvas` への低レベル入力や 3D 描画タイミングに強く依存するケースだけを E2E に残します。

## Test Hook

- `window.__goldbergTestState` は E2E のための補助 API です。
- UI の見た目確認ではなく、renderer/input 統合まわりの診断補助に使います。
- 実装を変える場合は、本番コードの責務を汚さず、シミュレーション state と描画コードの分離を崩さないようにしてください。

## Renderer

- Playwright などのブラウザ自動実行では、描画バックエンドは安定性優先で扱います。
- 自動実行時は WebGPU の可用性や入力処理の差異でフレークしやすいため、必要に応じて WebGL fallback を使います。
- この切り替えは CI 専用ではなく、ローカルの自動実行でも同じ前提に揃えます。

## When To Add Real UI Input Tests

- ボタンやフォームの配線そのものは、まず unit テストで検証してください。
- その場合も 1 テストで多くを検証せず、最小ケースに切り分けてください。
- `canvas` クリックやドラッグを残す場合は、失敗時に何が壊れたか分かるよう、対象を小さく保ってください。
