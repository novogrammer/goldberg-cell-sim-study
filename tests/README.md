# E2E Testing Notes

このプロジェクトの E2E は、ブラウザ操作の完全再現よりも CI での安定性と責務分離を優先します。

## 方針

- E2E は HUD 文言、主要コントロール表示、最小限の操作導線などのスモーク確認を担当します。
- シミュレーション状態遷移や描画依存の細かい挙動は、可能なら test hook を通して決定的に検証します。
- `canvas` への低レベル入力や 3D 描画タイミングに強く依存するケースは、E2E では最小限にとどめます。

## Test Hook

- `window.__goldbergTestState` は E2E のための補助 API です。
- UI の見た目確認ではなく、状態遷移の再現性を上げる目的で使います。
- 実装を変える場合は、本番コードの責務を汚さず、シミュレーション state と描画コードの分離を崩さないようにしてください。

## Renderer

- Playwright などのブラウザ自動実行では、描画バックエンドは安定性優先で扱います。
- 自動実行時は WebGPU の可用性や入力処理の差異でフレークしやすいため、必要に応じて WebGL fallback を使います。
- この切り替えは CI 専用ではなく、ローカルの自動実行でも同じ前提に揃えます。

## When To Add Real UI Input Tests

- ボタンやフォームの配線そのものを検証したい場合だけ、実クリックや実入力を使います。
- その場合も 1 テストで多くを検証せず、最小ケースに切り分けてください。
- `canvas` クリックやドラッグを残す場合は、失敗時に何が壊れたか分かるよう、対象を小さく保ってください。
