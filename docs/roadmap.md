# Roadmap

このドキュメントは、このリポジトリでこれから進める実装項目、改善候補、未決事項を整理するためのメモです。

- 現在の仕様や設計意図は `docs/simulation-model.md` を参照してください。
- 変更時に守る不変条件は `AGENTS.md` を参照してください。
- ここには「決まった仕様」ではなく、「これから進めること」を書きます。

## Goal

- このプロジェクトの目標は、状態変化を観測するためのデモに留まらず、眺めていられるプログラムに育てること
- そのために、ルールの正しさだけでなく、見た目の気持ちよさ、変化の連続性、眺めていて飽きにくい振る舞いを重視する
- 機能追加や調整は、解析しやすさだけでなく、鑑賞体験を良くするかどうかでも判断する

## Near Term

- WebGPU 前提の描画改善を、見た目と負荷の両面から整理する
- 植生表現を静的な配置だけでなく、軽いアニメーションも含めて検討する
- 3D 表示の構成を保ったまま、E2E テストを CI で安定して維持する

## Completed Recently

- `water` 固定セルの配置ルールを文書化した
- セルを直接ペイントして状態を切り替えられる編集モードを追加した
- クリックだけでなく、ドラッグで連続して塗れる操作を追加した
- ヘッドレスブラウザでのスモークテストを維持しつつ、canvas 操作の確認を追加した
- OrbitControls 依存をやめ、独自のカメラ制御へ置き換えた
- 自動回転、手動回転、ズームを整理し、編集モードと干渉しない入力モデルにした
- ペイントモード中はカメラが静止する回帰テストを追加した
- `WebGPURenderer` を前提にした描画構成へ移行した
- 地表セルを共通半球ジオメトリの `InstancedMesh` で描画する構成へ切り替えた
- 地表を `land` / `water` の 2 材質に分け、roughness 差を持たせた
- 植生を木と雑草に分け、どちらも `InstancedMesh` で最大数を確保する方式にした
- 植生の表示密度、サイズ、色を vegetation 量から決める構成にした
- hover / selected の表示を半透明ではなく球リング状 overlay で表現する構成にした
- WebGPU Inspector addon を追加し、webdriver 環境では無効化するようにした
- paint 系 E2E テストを、canvas UI 操作の flake を避ける test hook ベースへ整理した
- 現在の描画前提を `docs/rendering.md` として文書化した

## Next

- 地表と植生のアニメーションを GPU 側へ寄せられるかを検討する
- TSL を使って植生の揺れを軽く表現できるか調べる
- 地形や植生の変化が視覚的に読み取りやすい色・質感・動きの見せ方を考える
- 初期状態のランダム化や地形生成のバリエーションを増やす
- `water` / `land` 以外の種類もつくる
- 眺めていて単調になりにくい変化パターンを増やす
- 必要なら WebGPU 前提の描画テストと、描画に依存しないロジックテストの責務をさらに分ける

## Open Questions

- `water` は今後も固定地形のままにするのか、将来的に動的化するのか
- `state` を `vegetation` の別名として維持するか、将来別用途に広げるか
- 五角形セルを将来的に描画やルールで差別化する必要があるか
- 地表 overlay を今の単体 mesh のまま維持するか、将来的に別の instancing 戦略へ寄せるか
- WebGPU 専用表現をどこまで許容し、WebGL 互換をどこまで残すか

## Notes

- メッシュや更新ルールを変更する場合は、対応するテスト更新を優先する
- 五角形セルは除外しない
- 各セルの `neighbors`, `neighborCount`, `isPentagon` は常に維持する
- 描画改善を進めても、シミュレーション状態と描画コードの分離は維持する
- フロント変更では、コード確認だけで完了にせず、可能ならヘッドレスブラウザで確認する
